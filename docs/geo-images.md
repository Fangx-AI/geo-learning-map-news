# 公开资讯封面

2026-10-16 修复了公开资讯链路只保存文字的问题：共享 RSS 读取器原本能提供部分图片，但模块候选转换、存储表、公开 API 和阅读卡片均没有传递图片字段。当前链路为来源图片元数据 → 有效图片地址 → 独立字段存储 → 既有签名图片代理 → 卡片小封面。

## 采集与展示

- RSS/Atom 保留图片 enclosure、正文图片，并按公开资讯专用选项读取 `media:thumbnail`、图片类型 `media:content`、HTML 摘要图片；不因此把摘要升级为完整正文。图片解析版本进入条件请求校验，防止旧 304 缓存冻结新增字段。
- 缺图的直接文章读取 `og:image`、`twitter:image` 或 Article 类 JSON-LD image。只检查元数据，不采整篇正文，也不拿正文推荐栏图片、组织头像或站点 Logo 填空。
- 已发现的 X 原帖使用既有无登录公开嵌入读取器，取该帖自己的 `photos`，不取用户头像、引用帖或父帖图片。字段依据 [react-tweet 的公开 TweetPhoto 类型](https://github.com/vercel/react-tweet/blob/main/packages/react-tweet/src/api/types/photo.ts)。既有帖也进入独立补图队列，无须等待原帖刷新窗口。
- 索引结果、HN 讨论页及尚无可靠图片解析的 Reddit、知乎、小红书链接不补抓通用网页封面。Google 官方开发者文章仍可补查，不按整个 Google 域排除。
- 空地址、非公开地址、已知跟踪域、头像/Logo 路径和已知过小尺寸被过滤；验证页、登录页和访问失败不会发布为图片。
- 同 canonical 文章优先复用已有封面；RSS 已有封面不被较晚的网页请求覆盖。记录来源为 `rss`、`og-image`、`social`。
- API 仅返回同站签名 `/api/img-proxy` 地址，沿用已有网络保护、尺寸处理及缓存。代理参数含可查看的公开原图地址，不声称隐藏它。卡片为桌面约 112×75、手机 84×56，延迟加载，失败收起，不显示假图。原始媒体权利仍属于来源。

## 持续补查

每轮公开采集完成后，在同一 cycle 锁内执行最多 40 条封面补查；并发 2，每请求总预算 12 秒、2 MiB、最多 3 次同源跳转。图片字节仅由已有图片代理按阅读请求处理。不存在封面时 7 天后再查，读取失败时 1 天后再试；状态持久化，进程重启继续处理。来源已禁用的不再产生补查请求。

手动补历史封面可执行：

```powershell
node --env-file=.env modules/geo-directory/scripts/collect-images.ts --limit 200
```

需要 `PUBLIC_FEED_COLLECT_ENABLED=true`，与定时采集共用 cycle 锁，冲突时退出而非并行重抓。最大手动批次 500。无来源封面、公开访问失败、摘要图过小或页面无可靠元数据均允许保持纯文字。

## 验证

覆盖空地址、跟踪像素、OG/JSON-LD 尺寸、Atom HTML 摘要、RSS 解析版本刷新、X own-post photos、同文复用、并发写入不覆盖、持久化重试与请求预算。真实抽查 8 张 RSS/原文封面和 2 张 X 原帖图片，图片代理均返回 200 与有效图片字节；浏览器另检查自然尺寸及加载失败隐藏。精确数量见最新 [验收记录](geo-validation.md)。
