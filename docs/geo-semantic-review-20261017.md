# 2026-10-17 GEO 中文译文语义审阅

本轮对 60 条当前有效的外文标题、摘要和实际可见中文译文逐条核对，优先选择官方平台变化、论文和作者实测。它补充了[规则审计](geo-translation-audit.md)：规则负责发现可疑模式，语义审阅判断原文与译文的关系、限定和术语是否正确。

这是有目的的分层抽样，不是随机准确率评估，也不验证原文章主张的真实性。来源自身没有提供的内容不补写；旧快照中的错误必须在当前原文与实际可见译文中重新确认。

实际语种分布为英语 48、法语 4、德语 3、日语 2、西班牙语 2、葡萄牙语 1。英语样本中有两条原始语言字段为 `und`；审阅保留数据库字段，没有改写来源元数据。

19 条语义或术语问题提供了可应用的完整修订标题与摘要；另有 6 条提供可选的阅读优化，其余可读性问题没有强制改写。已有的 5 条审核修订全部排除。31 条候选的原文相较旧快照已经变化，审阅改用当前完整摘要重新判断，旧版 Ahrefs 年份、葡语媒体归属和 AEO 等已解决问题没有计入当前错误。

## 代表性变更

| 原文片段 | 旧译问题 | 修订表达与依据 |
| --- | --- | --- |
| `Sites Cited` | “引用网站数”容易颠倒方向 | “被引用网站数”，表明网站是被 AI 引用的一方。 |
| `remain poorly understood` | “影响仍不充分” | “影响仍缺乏充分理解”，区分认识不足与影响程度低。 |
| `need not represent actual user demand` | “不必代表实际用户需求” | “未必代表真实用户需求”，保留研究有效性的限制。 |
| `defending generative search engines against malicious ...` | 把搜索引擎写成攻击方 | “保护生成式搜索引擎，使其免受恶意 GEO 的影响”。 |
| `perplexity filtering` / `perplexity ratio` | 当作 Perplexity 产品名 | “困惑度过滤”／“困惑度比率”，与文中的统计量语境对应。 |
| `Grounding` | “基础技术”／“基座” | 保留术语并说明为回答提供信息依据，避免与模型基座混淆。 |
| `GEO`（法语、西语标题） | “地理”／“地理技术” | 保留 GEO；媒体署名与陈述主体分开。 |
| `production web search` | “生产网页搜索” | “线上搜索研究”；摘要保留模型名，把 URL、主机名、实体明确写作分析层级。 |

## 修订的最终复核

25 条候选修订又逐条与完整已采集原文对照，检查了攻击者与被保护对象、比较方向、否定、可能性、数字、日期、模型名、来源署名及截断边界。

- GEO Defender 仍以生成式搜索引擎为被保护方，保留两项防御难点和“无需微调目标模型”的限定；困惑度指标没有改成产品或服务能力。
- CHASE 保留 `0.853 ± 0.093`、六个领域和 20 轮；竞争性引用研究保留 252,000 次试验、18 个因素与每次恰好一个因素变化，没有添加“完全因子”或具体交替顺序的实验断言。
- `can alter` 使用“可能改变”；未将研究中的可能性改成必然性。对内容 `presence` 没有额外指定原文未给出的频率指标。
- ChatGPT 引用论文保留 `ChatGPT 5.2` 至 `5.5`、`Instant`、`Thinking` 与 `GPT-5.4 Thinking`。URL、主机名和实体是分析层级，不是模式的属性。
- 截断标题 `whether adding "Offi…` 只译到“是否添加……”。完整摘要里的 `official`、`Official Site` 保留为实际操作字符串，不用摘要补齐原标题。
- Google 的 `we’re evolving our pa…` 译到“我们正在调整……”，不猜测 `pa` 后面是什么。案例文章的 `and the subject ...` 保留为“邮件主题是……”，不补邮件内容。
- “下滑”没有擅自具体化为原文片段未明说的“流量下滑”。源摘要结尾的省略仍保留，不用全文或外部信息续写。

本轮本地审阅产物是 `.data/translation-semantic-review-20261017.json`、`.data/translation-semantic-references-20261017.jsonl` 和 `.data/translation-readability-references-20261017.jsonl`，它们包含精确原文、原文 hash、采样时的实际译文及完整建议。`.data/` 不提交仓库。

修订文件通过现有修复 CLI 的只读预演后，仍需由维护者统一决定应用。应用必须匹配当前原文版本，继续遵循[译文维护流程](geo-translation-quality.md)与[审核修订规则](geo-corrections.md)。此审阅任务没有写入数据库，也没有调用翻译或模型服务。

## 全库规则候选的追加复核

随后使用涵盖 1,168 条内容的规则审计快照，逐条复核剩余 23 条可见候选，排除前述 25 稿及已有审核修订。此集合与 60 条抽样部分重合，不能相加作为独立样本总数。

确认另外 4 条 GEO 被误译为地理概念，以及 5 条术语或来源名称问题：Claude Code、Show HN、Google 搜索政策术语、域名可见性和 Clarity 的引荐访问。其余 14 条保留原状，包括正确的主动引用句、Perplexity 平台名、合法数字写法，以及来源摘要本身携带的导航尾注。

例如，`domain visibility` 在按网站引用份额衡量的论文中应译为“域名可见性”，而不是“领域可见性”；`Scrape-to-Referral Insights` 中的 referral 指引荐访问，不能写成内容推荐。`Social GEO`、`GEO` 仍保留为行业术语，不扩写成原文没有的具体定义。

追加结果保存在 `.data/translation-semantic-audit-followup-20261017.json`。不受摘要清理影响的 7 稿位于 `.data/translation-semantic-extra-references-20261017.jsonl`。Clarity 与 Claude Code 两稿因原摘要需要清理尾注，先保存在 `.data/translation-semantic-awaiting-summary-refresh-20261017.jsonl`，并标记 `publishable: false`。这个旧稿文件继续保留作历史记录，不应用过期稿件。

8 条源摘要清理到 `summary_version=2` 并重新翻译后，又从数据库读取当前原文与实际译文逐条复核。Clarity 与 Claude Code 的两个问题仍在，已按新 hash 重新编写；同时发现 Search Engine Journal 的新标题把“AI 推荐哪个品牌”误挂为“品牌 AI 的推荐”，增加一条标题修订。其余 5 条未发现新增实质错误。3 条新稿位于 `.data/translation-summary-v2-references-20261017.jsonl`，8 条复核记录位于 `.data/translation-semantic-summary-v2-review.json`。三稿再次通过只读预演，原文版本匹配；来源自身残缺的摘要仍保持缺文。
